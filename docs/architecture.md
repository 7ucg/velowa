# velowa architecture

## Toolchain (TS side)

| Concern | Choice | Why |
| --- | --- | --- |
| Build | `tsup` (esbuild), ESM **and** CommonJS, `tsc --noEmit` for the type check | One source, two formats: `dist/index.js` + `dist/index.d.ts` for `import`, `dist/index.cjs` + `dist/index.d.cts` for `require`; no source maps. The generated WASM glue is bundled, the `.wasm` files and `WAProto.proto` are copied next to the bundles (`scripts/copy-assets.mjs`). `npm run check:package` runs `publint` and `attw`. |
| Tests | `vitest` | Runs TS/ESM natively; `ts-jest` + ESM is a known pain point. Same `describe/it/expect` shape. |
| Lint/format | `eslint` 9 flat config + `typescript-eslint`, `prettier` | Standard; type-aware rules catch missed union cases. |
| WASM loader | generated `wasm-pack --target web` glue, loaded with `initSync(readFileSync(...))` | Works on Node >= 18 with no bundler and no `fetch` of a file URL; browsers use the default async init. |
| Protobuf (TS side) | `protobufjs` | Must cover the full `WAProto` (Rust only needs 35 types). `protoc` rejects the Baileys schema's top-level enum value collisions (see `docs/waproto.md`), which also rules out `protoc-gen-es`; `protobufjs` tolerates the schema as it is. |

## Layout

```text
src/
  wasm/ wasm-voip/   generated by wasm-pack (gitignored); never imported outside codec/, crypto/ and voip-wasm.ts
  codec/             WABinary: BinaryNode types + encode/decode wrapper over the wasm binding
  crypto/            noise, signal, appstate wrappers - stateful classes, not free functions
  auth/              credentials + stores (memory, file); the library never decides where state lives
  events/            typed event bus
  logging/           protocol logger
  wam/               WhatsApp analytics (WAM) encoder
  cli/               pairing helper
  client/
    client.ts        Client: the public API surface, one method per feature
    connection.ts  receiver.ts  sender.ts  pairing.ts  ...   the engine behind it
    features/        request builders and parsers, one folder per domain, no I/O of their own
      account/  call/  channel/  chat/  community/  contact/  group/  message/  payment/  report/
  index.ts           public API; everything else is internal
tests/               mirrors src/ one to one (tests/client/features/call/calls.test.ts tests src/client/features/call/calls.ts)
  helpers/           shared test fixtures (`*.testkit.ts`): a fake remote world, app-state helpers
  codec/fixtures/    captured stanzas
```

Feature folders: `call` (stanzas, media session, local audio, files as media), `channel` (newsletters),
`community`, `group`, `message` (builders for texts, polls, buttons, rich responses, media, link previews,
receipts/presence parsing), `chat` (app-state sync, chat actions, history), `contact` (lookup, usernames,
business profiles), `payment`, `report`, `account` (pairing code). `features/mex.ts` is the shared GraphQL
helper.

Rule: dependencies point downwards only (`features -> client -> crypto/codec/auth/transport`). `codec`
and `crypto` do not know about `client`.

## Event model

A small typed bus: `client.on('message', (m) => ...)` returns an unsubscribe function, and
`client.events('message')` returns an `AsyncIterable` for `for await` consumption. Event payloads are
discriminated unions keyed by `type`, so a missed case fails `tsc`. Chosen over Node's `EventEmitter`
because it is untyped per event, and over async-iterator-only because most consumers want simple
callbacks. Implemented in `src/events/emitter.ts`.

## Auth state

`AuthStore` is a small async key-value interface (`get/set/delete` per typed key group, batch `set`
for atomic writes), not Baileys' `{ creds, keys }` shape. The library supplies memory and file
implementations; SQLite/Redis are consumer-provided. Signal session writes must be durable before the
corresponding ack is sent (`whatsapp-rust agent_docs/signal_durability.md`) - the interface is
therefore `Promise`-returning throughout.

## Rust binding

Default: stateful wasm-bindgen classes exposed directly when the generated `.d.ts` reads well, a thin
hand-written TS wrapper only where it adds real value (ergonomic types for `BinaryNode`, error
mapping). See `docs/design-decisions.md` for the choice made per subsystem.
